# PrankCreation — Leçons

> Format : [date] | ce qui a mal tourné / le piège | règle pour l'éviter

- 2026-06-01 | Le prompt indiquait `🇹🇭 Bali`, or Bali est en Indonésie. | Toujours vérifier la cohérence drapeau/pays — Bali = 🇮🇩 Indonésie.
- 2026-06-01 | Premise technique fragile : « FLUX img2img pour préserver le visage ». img2img re-génère toute l'image et ne conserve pas l'identité. | Pour garder le visage dans un nouveau décor, utiliser une méthode identité (InstantID / PuLID / IP-Adapter FaceID) ou face-swap + compositing. À trancher à l'étape 3.
- 2026-06-01 | Pas de clés API en session 1. | Tout ce qui dépend de Replicate/Supabase/Stripe reste en stub visuel honnête (jamais de faux résultat affiché comme réel).
- 2026-06-01 | Limite « 200 car » posée uniquement via l'attribut HTML `maxLength` : ne bride que la saisie clavier/paste ; une valeur arrivant autrement passe à 240, et ce texte part dans le prompt Replicate. | Appliquer toute limite métier dans le handler `onChange` (`value.slice(0, MAX)`) EN PLUS de `maxLength` — la règle doit vivre dans l'état React, pas seulement dans le DOM.
- 2026-06-01 | Vérif preview : `preview_click` renvoie « success » mais ne déclenche pas toujours le `onClick` React (state inchangé) — fait perdre du temps. | Pour tester un handler React, dispatcher un vrai click natif via `eval` (`el.click()`) puis attendre un tick (~60 ms) avant de relire le DOM/état.
- 2026-06-01 | Nouvelle animation ajoutée dans `tailwind.config.js` (`animate-marquee`) absente du CSS compilé : `animationName: none`, keyframes inexistantes — le HMR Vite ne recharge PAS la config Tailwind. | Après toute modif de `tailwind.config.js` (couleurs, keyframes, animations…), redémarrer le serveur de dev (stop + start), puis vérifier la règle compilée (`getComputedStyle`/scan `styleSheets`) avant de conclure.
- 2026-06-02 | Edit « String to replace not found » sur un bloc pourtant identique à l'écran : le fichier contenait une espace insécable (U+00A0) là où je tapais une espace normale (`: '\xa0'` dans `PlanCard.jsx`). Read l'affiche comme un espace banal. | Quand un Edit échoue sur du texte visuellement identique, vérifier les octets réels (`python3 -c "print(repr(ligne))"`) avant de réessayer ; ancrer le match sur une sous-ligne **pur ASCII**, ou faire le remplacement en Python avec le caractère exact.
- 2026-06-02 | Serveur de preview d'une session précédente injoignable : `preview_list` vide + `preview_eval` « Server not found » alors que le process Vite semblait vivant (puis port 5180 libre). Aucun `.claude/launch.json`. | Ne jamais réutiliser un `serverId` d'une session antérieure sans le revalider via `preview_list`. Créer `.claude/launch.json` (config nommée + port) et (re)lancer via `preview_start` (réutilise si déjà up) plutôt que `vite` en Bash.
- 2026-06-02 | `preview_eval` qui fait `location.href = …` PUIS continue à lire le DOM dans la même expression → « Inspected target navigated or closed ». | Naviguer dans un eval, lire dans l'eval **suivant** (1 appel pour naviguer, 1 appel séparé après settle pour lire).
- 2026-06-01 | Suppression de `Navbar.jsx` alors qu'il était encore importé l'instant d'avant : le HMR Vite a loggé « [hmr] Failed to reload Navbar.jsx » + des erreurs React du parent `<Landing>` qui ont PERSISTÉ dans le buffer console (même timestamp HMR figé `?t=…`) même après un `location.reload()`, alors que l'appli rendait parfaitement. Faux positif → perte de temps. | Juger la santé sur le **rendu DOM réel** (h1/nav présents = pas de throw, car aucun error boundary), pas sur le buffer console. Après suppression/déplacement d'un module, faire un **stop+start** du serveur pour purger le graphe HMR et le buffer avant de lire les erreurs « propres ».
- 2026-06-02 | Ajout d'une nouvelle fonction `IconSnap` + nouvelle entrée dans le `const nav = [...]` de `Sidebar.jsx` (code valide : déclarations de fonction hoistées, exactement comme les `IconHome`/`IconStudio` existants) → React Fast Refresh a échoué (« [hmr] Failed to reload Sidebar.jsx ») et laissé un `ReferenceError: IconSnap is not defined` FIGÉ dans le buffer (timestamp `?t=…`), alors que la sidebar + le h1 rendaient. Même cause/remède que la suppression de module, mais déclenché par un **ajout**. | Avant de « corriger » un ReferenceError après un gros lot de changements (nouveaux hooks/composants + imports), vérifier le code (hoisting = valide) puis **stop+start** pour purger le graphe HMR ; rejuger sur le DOM réel. Ne pas réécrire du code correct à cause d'un faux positif HMR.
- 2026-06-02 | Check d'overflow mobile « par élément » trompeur : comparer `child.getBoundingClientRect().right` au bord du parent renvoyait « +63 px » alarmant — c'était juste le halo décoratif `aria-hidden` (`absolute -right-16 … blur-[90px]`), volontairement débordant et **clippé par `overflow-hidden`** de la carte. Aucun scroll de page. | Pour juger un overflow horizontal, mesurer au **niveau document** : `documentElement.scrollWidth - clientWidth` (0 = OK). Les blurs/halos en offset négatif (`-right-16`, `-top-20`) sont du décor clippé — les exclure (filtrer `aria-hidden`/`blur-`) avant de conclure à un bug.
- 2026-06-02 | Vérif d'une notice dynamique via recherche texte large (`querySelectorAll('p').find(includes('paiement unique') && includes('Stripe'))`) → faux positif : a matché la note **statique** de `SnapTip`, pas la notice rendue au clic. | Pour vérifier un toast/notice dynamique, cibler son **conteneur unique** (classe propre, ex. `.border-gold\\/20`) et lire son `textContent`, pas un scan de toute la page sur des mots-clés partagés.
- 2026-06-03 | `find … -name … -exec perl …` a échoué : le `find` sandboxé ne supporte pas les prédicats/actions composés (« rtk find does not support compound predicates or actions ») → le rename or→bleu n'a jamais tourné (faux sentiment de succès). | Pour un remplacement de masse, ne pas compter sur `find -exec`. Utiliser `for f in $(grep -rl "motif" src --include='*.jsx'); do perl -i -pe 's/…/…/g' "$f"; done` (ou `xargs`), puis **vérifier par grep** que le motif a disparu avant de conclure.
- 2026-06-03 | Migration de couleur de masse `s/gold/bleu/g` : risquait d'écraser le mot métier réel **`golden`** (style d'éclairage « Golden hour » utilisé dans les prompts Replicate de `STYLE_PROMPTS`). | Pour renommer un token qui est un préfixe d'un autre mot légitime, utiliser un lookahead négatif : `s/gold(?!en)/bleu/g`. Toujours se demander si la chaîne cible est sous-chaîne d'un terme à préserver avant un remplacement global.
- 2026-06-03 | Après un `perl -i` (édition hors-outil) sur des fichiers déjà lus en contexte, l'outil `Edit` a refusé (« File has not been read yet ») : la modif externe a invalidé l'empreinte de lecture de la session. | Toute édition par script externe (`perl`/`sed`/`for`) invalide les `Read` en cache. **Re-`Read` chaque fichier touché par le script avant de l'éditer** avec l'outil Edit.
- 2026-06-03 | Sous-agents parallèles sur un même rebrand : risque de conflit d'écriture + de dérive de ton/contenu. | Découper en **jeux de fichiers disjoints** (un agent = un set, aucun fichier partagé), fournir une **spec de marque commune** + contraintes verbatim (prix au mot près, frontière de contenu, stub honnête), et **interdire aux agents de toucher la config/redémarrer le serveur** (réservé au parent). Toujours « trust but verify » : relire les diffs réels, ne pas se fier au résumé de l'agent.
- 2026-06-03 | `SnapTip.jsx` cherché dans `components/landing/` alors qu'il est dans `components/pricing/` → Read en échec. | Ne pas deviner l'emplacement d'un composant ; `grep -rl` ou `find` le chemin réel avant de Read/Edit (le dossier ne reflète pas toujours la section d'affichage).
- 2026-06-02 | `preview_screenshot` rend dans un viewport différent (≈1600×912) de celui de `preview_eval` (1280×720 / 375×812) : un `scrollTop` posé via eval ne se reflète pas dans la capture, et `scroll-behavior: smooth` (index.css) fait que la lecture immédiate de `scrollTop` renvoie une valeur mi-animation (ex. 110 puis clamp à 801). Résultat : captures « scrollées » en écran noir trompeur (on tombe sur le bas opaque `to-noir` d'un overlay). | Pour du contenu **hors écran**, se fier aux assertions DOM (texte/classe présents, `getBoundingClientRect`), pas au screenshot. Si scroll requis : `scrollIntoView({behavior:'instant'})` et ne pas croire le `scrollTop` lu juste après. Le screenshot reste fiable surtout en haut de page.
- 2026-06-04 | Vérifier un endpoint de génération « sans clé API » semble bloqué (pas de token → on ne peut rien tester). | Réordonner la **validation d'input AVANT le check de clé** (validation à la frontière) rend toutes les branches testables token vide : un seul `preview_eval` (IIFE qui POST plusieurs payloads) prouve d'un coup le contrat ET la sécurité — input valide→`503 no_key` (stub honnête), prompt vide→`400`, **URL en guise d'image→`400` (anti-SSRF : le serveur refuse de fetch une URL client)**, image absente→`400`. Toujours inclure le cas SSRF (`https://…` comme image) dans le jeu de test.
- 2026-06-04 | Après réécriture d'un modèle (InstantID/FLUX → nano-banana), du **code mort en commentaire** subsistait (`UploadPanel.jsx` : « routage InstantID vs FLUX ») — invisible au grep des symboles de code. | Après un changement de modèle/API, grep aussi les **commentaires** (noms d'anciens modèles : `InstantID`, `flux`, `instant-id`) en plus des symboles. `server/lib/*` ne passe pas par le HMR Vite → **stop+start** obligatoire avant de vérifier les imports.
- 2026-06-06 | A/B Replicate `nano-banana-pro` + `seedream-4.5` lancés **en parallèle** → `429 Too Many Requests` (compte avec <5 $ de crédit : rate limit réduit à ~6/min, burst=1). seedream a réussi, nano-pro a pris le 429 → faux signal « nano-pro casse ». | Sur un compte Replicate à faible crédit, **lancer les appels en SÉRIE** (jamais en parallèle), et prévoir un arg `only` pour ne relancer qu'un modèle (éviter de re-dépenser pour une sortie déjà obtenue). - 2026-06-06 | `npx vite build` → « Missing script: vite » ; `npm run build` → « Missing script: run ».
